## Project context

**FF-NEXUS** is a futuristic, cinematic informational portal for the Free Fire community: news, events, tournaments, rankings, guides, rewards, codes, community. The visual target is "AAA gaming HUD × cyberpunk eSports" — not a generic content site. Every UI decision should reinforce that feel.

The site is fan-made and **not affiliated** with Garena / 111 Dots Studio (see `src/config/site.ts`).

## High-level architecture

Two organising principles work together:

1. **Atomic / role-based layering** under `src/components/`:
   - `ui/` — primitives (Button, Badge) with `cva` variants
   - `effects/` — visual-only components (GlassCard, NeonText, Scanlines, future Particles/Holo)
   - `layout/` — Header, Footer, MobileNav, etc.
   - `sections/` — full landing sections like `HeroCinematic`
   - `icons/` — custom SVGs (lucide handles the rest)

2. **Feature-sliced domains** under `src/features/<domain>/`:
   - One folder per business domain (`news`, `tournaments`, `ranking`, `rewards`, `codes`, `community`, `guides`, `events`)
   - Each owns its own `components/`, `api/`, `hooks/`, `types.ts`. **Features must not import from sibling features** — cross-feature work happens through `src/lib/` or shared `src/components/`.

`src/app/` is route-only. Marketing routes live in the `(marketing)` route group, legal in `(legal)`. Heavy logic belongs in `features/` or `lib/`, never in `app/`.

Other key folders:

- `src/lib/cms`, `src/lib/api`, `src/lib/seo`, `src/lib/analytics` — integration layers (Sanity, fetchers, JSON-LD/OG, etc.)
- `src/config/` — typed config: `site.ts`, `nav.ts`, `env.ts` (Zod-validated env)
- `src/styles/` — `tokens.css` (CSS variables for colors, gradients, easing, durations) and `animations.css` (keyframes + `prefers-reduced-motion` guard)
- `src/stores/`, `src/hooks/`, `src/types/` — global state, hooks, shared types

The full architectural rationale lives in the planning doc the user shared when scaffolding. Honour the boundaries it sets.

## Server Components are the default

Components are RSC unless they need interactivity. Only add `"use client"` when the component uses hooks, browser APIs, or event handlers. Animated sections (Framer Motion, GSAP, R3F) are client components and should be the leaves of the tree — keep the surrounding layout server-rendered.

## Design system rules

- **Never use raw color literals.** Always go through the tokens in `src/styles/tokens.css`, surfaced as `bg-ff-yellow`, `text-ff-orange`, `text-grad-fire`, `bg-glass`, `shadow-[var(--shadow-glow-yellow)]`, etc.
- The brand palette is fixed: `#000000`, `#121212`, `#FFB900`, `#FF7A00`, `#FF3B30`, `#FFFFFF`. Adding a new color requires adding a token first.
- Fonts: `font-display` (Orbitron) for H1–H4 and big numbers, `font-heading` (Rajdhani) for labels/CTAs, `font-sans` (Inter) for body, `font-mono` (JetBrains Mono) for codes/metadata.
- Animation rules: only `transform` + `opacity`; canonical durations are `--dur-micro`, `--dur-ui`, `--dur-section`, `--dur-hero`; canonical easing is `--ease-out-expo`. Respect `prefers-reduced-motion` (the global reset is already in `animations.css`).
- Component variants go through `cva`, not ad-hoc prop branches. See `src/components/ui/Button.tsx` for the pattern.

## Next.js 16 gotchas (training data is likely pre-16)

These are the breaking changes most likely to trip up code generation. Always confirm with `node_modules/next/dist/docs/` if unsure.

- `cookies()`, `headers()`, `draftMode()`, and `params` / `searchParams` props are **async** — they return Promises and must be `await`ed. Use the global `PageProps<'/route'>` / `LayoutProps<'/route'>` / `RouteContext<'/route'>` helpers (generated by `next dev`/`build`/`typegen`) instead of hand-rolled prop types.
- `middleware.ts` is deprecated → use `proxy.ts` with a `proxy()` export. The `proxy` runtime is `nodejs` only; keep `middleware.ts` if you specifically need the `edge` runtime.
- `next lint` was removed. Use `pnpm lint` (ESLint CLI) directly. `next build` no longer runs linting.
- `experimental.ppr` and `experimental.dynamicIO` are gone; PPR opt-in is now `cacheComponents: true` at the top level of `next.config.ts`.
- `revalidateTag('tag')` now requires a `cacheLife` profile as the second argument; use `updateTag()` (server-actions only) when you need read-your-writes semantics.
- `cacheLife` / `cacheTag` are stable — drop the `unstable_` prefix.
- All parallel-route slots require an explicit `default.tsx`.
- `next/image`: `domains` is deprecated (use `remotePatterns`); `localPatterns.search` is required for local images with query strings; default `minimumCacheTTL` is now 4h; default `qualities` is `[75]`; local-IP optimisation is blocked unless `dangerouslyAllowLocalIP` is set.
- AMP, `next/legacy/image`, `serverRuntimeConfig`, `publicRuntimeConfig`, and `unstable_rootParams` are all removed.
- The build output no longer shows `size` / `First Load JS`. Measure with Lighthouse / Vercel Analytics.
- `next dev` writes to `.next/dev`, `next build` to `.next/build` — they can run concurrently.

## Performance budget

The plan commits to: Lighthouse Performance ≥ 95, LCP < 2.0s, INP < 200ms, CLS < 0.05, initial JS < 180 KB, total page < 1.5 MB. Treat regressions on these as build-breaking.
